## 6. 簡體掃描的實作提示
- 只用 Big5-HKSCS 判定會漏掉數百行（它收了部分簡體字）；cp950 判定較嚴，但仍漏掉 Big5 本來就收的簡體字形（例如「裡、鬆、復、並、與、採、準、製、餘、後」各字的簡體寫法）。
- 需要再加「轉換器重轉一次是否改變」與固定樣式清單；有些詞（例如「下拉裡」「卡裡」「鬆鍵」的簡體寫法）重轉也不會變，要列樣式。
- 轉換器會誤改正體用詞（只→隻、通過→透過、免提→擴音、百煉→百鍊、拷貝→複製等），批次轉換後一定要複查。
- 白名單候選：轉換模組中說明歧義字的註解、`tools/zh-crosstest` 的正體樣本（里長、鄰里、于先生）、正體用法的「干擾、散布、克制、強制」、〇、⋯、幺，以及轉換模組與測試工具的簡體字表。

- 清理分支時另做過的方法：把每一行再過一次 s2twp（含「臺→台」），列出會變的行人工判斷。
- 其他實測過的誤轉：資源文件→資原始檔、連接→連線、添加→新增、賬沒有轉成帳。註解裡仍有偏大陸說法的用詞（文本、識別等）未逐行檢查。
- 白名單每筆要寫理由，掃描要附負向測試（放一個簡體字必須失敗）與圖片人工清單。安全紀錄下一個編號是 SC-72。

## 10. 經驗
- 每個合併前做一次獨立覆核；覆核最常抓到的是「整個介面某處漏改」「條件太寬或太窄」「文件寫的比實作多」。
- 覆核用 `git worktree add --detach`，不要在共用工作目錄切換分支。
- 分支先推送，雲端測試與覆核可以並行。
- 雲端用不同機器與版本，抓得到本機看不到的問題（舊版 Rust 的錯誤碼）。
- 派「雲端」工作後先確認實際執行環境。
- 測試資料不要寫死格式假設（WAV 標頭長度）。
- 大量文字轉換不能只靠一種判定方式，轉完要抽查程式中比對用的字串。
- 有些 shell 的 heredoc／echo 會把 `\uXXXX` 解成字元，含跳脫的檔案用腳本寫入。
- 多行 import 區塊中間插入新 import 會讓 `tsc` 失敗；新增 i18n 例外要加 `i18n-allow` 標記。
